## 文档模板填充系统设计蓝图

### 1. 总体架构
- **前端层：** 基于 Vite + React + TypeScript + Tailwind，构建模板选择、动态表单、任务状态与下载管理界面。使用 React Query 管理接口数据；表单使用 React Hook Form + Zod。
- **后端层：** FastAPI 提供 REST API，拆分为模板管理、任务调度、渲染转换、文件下载等路由；采用 Pydantic v2 定义请求/响应模型。
- **任务执行层：** MVP 使用 FastAPI BackgroundTasks 处理渲染与转换；为未来迁移 Celery/Redis 预留接口封装（`TaskExecutor` 抽象）。
- **渲染引擎层：** 封装 DOCX/PDF 渲染、格式转换和文件归档，统一异常处理与日志。
- **存储层：** 关系型数据库（Postgres）保存模板、任务、结果元数据；本地文件系统存储模板文件与输出结果，后续可替换为对象存储。

### 2. 模块划分
| 模块 | 主要职责 | 关键实现 |
| --- | --- | --- |
| `TemplateService` | 加载与缓存模板元数据，提供列表与详情 | 读取 `templates/<id>/metadata.json`，使用 LRU/Redis 缓存 |
| `RenderService` | 支持 DOCX/PDF 渲染 | DOCX 使用 `docxtpl`，PDF 使用 `xfdfgen`+`pikepdf`，封装输入校验 |
| `ConversionPipeline` | 将基础文件转换为目标格式 | LibreOffice/Pandoc/Imagemagick + 可配置步骤 |
| `TaskService` | 管理任务生命周期、状态、结果记录 | 数据库存储 + BackgroundTasks 执行 |
| `FileArchive` | 临时目录与结果归档、清理 | 使用 `tempfile` 创建任务目录；周期性清理过期文件 |
| `HealthCheck` | 监控依赖状态 | 启动与定时运行外部命令探测 |

前端组件按页面划分：模板浏览、动态表单、输出选项、任务列表、下载中心、设置面板；共用组件库提供表单控件、进度条、弹窗、通知等。

### 3. 数据与流程
1. **模板加载：** 后端启动时扫描 `templates/`，校验 `metadata.json`，构建缓存。前端访问 `GET /api/templates` 获取列表。
2. **任务创建：** 前端提交 `RenderRequest`（模板 ID、数据、输出格式、选项）；后端校验后写入 `tasks` 表，异步执行渲染任务。
3. **渲染转换：**
   - DOCX：`docxtpl` 渲染 → 保存 DOCX → 调用 LibreOffice 转 PDF → 调用 Pandoc 产出 HTML/Markdown/RTF/TeX。
   - PDF：构建 XFDF → `pikepdf` 写入 → 视配置调用 `ghostscript` 扁平化或生成 PDF/A。
4. **结果归档：** 输出文件写入 `results/<task_id>/`；生成 `task_results` 记录及下载 token。
5. **任务查询与下载：** 前端轮询或订阅进度接口，完成后下载单个文件或打包 Zip。
6. **清理：** 定时任务扫描数据库中过期记录，删除对应文件并更新状态。

数据模型（概述）：
- `templates(id, name, description, version, status, updated_at, config_hash)`
- `tasks(id, template_id, status, requested_formats, options, progress, error_code, created_at, expires_at)`
- `task_results(id, task_id, format, file_path, file_size, checksum, download_token, expires_at)`
- `task_logs(id, task_id, level, message, payload, created_at)`

### 4. 运行与部署
- **本地开发：** `docker-compose` 启动 FastAPI、前端、数据库、Redis（可选），挂载模板目录；提供 Makefile/justfile 快捷命令。
- **CI/CD：** GitHub Actions 运行 linters（Ruff、ESLint）、测试（Pytest、Vitest）、构建镜像并推送；部署阶段执行数据库迁移与健康检查。
- **生产环境：** 建议在 Kubernetes 部署，使用 HPA 控制服务扩缩；静态前端部署至 CDN；后端容器挂载持久卷存储模板与结果文件。

### 5. 安全与可 observability
- **安全：** 限制文件上传类型与大小；对下载链接使用短期 token；记录操作日志。
- **可观测性：** 接入 Prometheus（任务耗时、成功率、外部命令失败次数）；使用 OpenTelemetry 导出链路追踪；集中化日志（ELK/云厂商服务）。

### 6. 演进路线
1. 阶段一：MVP 架构落地（无鉴权、BackgroundTasks、文件系统存储）。
2. 阶段二：引入 Celery + Redis 队列、对象存储、模板上传审核流。
3. 阶段三：多租户与权限控制、国际化 UI、可视化模板编辑器。
