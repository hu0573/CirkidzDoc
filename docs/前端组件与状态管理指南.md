# 前端组件与状态管理指南

## 总览

本文档介绍文档模板填充控制台的前端实现方式，帮助开发者快速理解组件职责、状态流转以及后续扩展原则。当前前端基于 React 19 + TypeScript + TailwindCSS 构建，并引入 React Query、React Hook Form 与 Axios 完成数据获取与表单管理。

整体结构按照“列表选择 → 动态表单 → 任务中心”划分成三大区域，对应的核心组件分别为：

- `TemplateList`：模板列表与选中态展示。
- `TemplateDetailPanel`：根据模板元数据动态生成表单、输出格式配置与高级选项。
- `TaskCenter`：展示当前任务轮询状态与历史记录，并提供结果下载与重试能力。

## 数据获取与缓存

- `src/lib/apiClient.ts` 定义 Axios 实例，统一配置 `baseURL`、超时、错误拦截与文件下载辅助函数。下载函数会根据后端返回的相对或绝对路径自动拼接请求地址，并处理 `Content-Disposition` 中的文件名。
- `src/lib/api.ts` 封装模板、格式、渲染任务相关的 API 调用。所有请求均返回强类型对象，便于在组件中获得即时类型提示。
- React Query 在 `src/main.tsx` 中通过 `QueryClientProvider` 注册，默认禁用窗口聚焦时自动刷新并设置单次重试。这样在弱网场景下既能避免过度请求，又能兼顾稳定性。
- `App` 组件中使用的查询：
  - `['templates']`：拉取模板列表并在初次加载时自动选中第一个模板。
  - `['template', templateId]`：拉取选中模板的详情。变更选中项时仅刷新对应数据，避免全局刷新。
  - `['formats']`：获取后端支持的输出格式描述与 PDF 高级配置能力。
  - `['taskStatus', taskId]`：轮询当前任务状态。轮询间隔 2 秒，当任务进入 `succeeded` 或 `failed` 后自动停止。

## 表单构建与校验

- `TemplateDetailPanel` 利用模板字段元数据 `FieldSchema` 动态渲染输入控件，支持 `string`、`number`、`boolean`、`date`、`enum`、`textarea` 与 `file` 类型。
- 组件内部通过 React Hook Form 统一管理字段值、校验与错误提示。`ValidationRule` 中的必填、长度、范围、正则等校验规则会自动转化为表单校验逻辑。
- 文件字段在前端转为 Base64 字符串后随 JSON 一并提交。默认限制单文件 20MB，可在组件中按需调整。若需要改为分片/表单上传，可在此处替换为上传接口并传递文件 token。
- 输出格式选择通过 `OutputFormatSelector` 实现，可展示后端提供的格式描述。表单提交前至少需要选择一种格式，否则给予错误提示。
- 当勾选 `PDF` 输出时，组件会读取模板元数据中的 PDF 能力开关，动态展示扁平化、PDF/A、密码等高级选项，并仅在用户启用时向后端传递参数。

## 任务状态与下载管理

- `TaskCenter` 分为“当前任务”与“历史记录”两部分：
  - 当前任务：展示任务 ID、实时进度条、状态徽标、失败原因及已生成结果。若任务失败，可直接发起重试。
  - 历史记录：按时间倒序保存最近 10 条。列表支持快速下载指定格式，并对失败任务提供重试入口。
- 重试逻辑：`App` 组件会缓存每个任务的请求参数（`RenderRequestPayload`）。当用户在任务中心点击“重试”时，复用原始参数重新发起渲染。若找不到缓存（例如历史过久被清空），会提示用户重新填写表单。
- 下载逻辑：借助 `downloadFile` 辅助函数自动触发浏览器下载，并兼容后端返回的相对/绝对链接。若请求失败或网络异常，错误信息会统一反馈到顶部告警栏。

## 错误处理与提示策略

- API 访问失败、轮询异常或任务执行失败时，均会调用 `pickErrorMessage` 将错误统一转为易读中文信息，并显示在页面顶部的红色提示区域。
- 模板详情加载失败时，会在模板列表右侧显示错误卡片，避免遮挡其他内容。
- 表单字段错误（包含文件校验）在输入控件下方以红色文案提示，帮助用户快速定位问题。
- “清空历史”按钮可在任务中心右上角清除历史记录及告警文案，便于重新测试。

## 组件职责与扩展建议

| 模块 | 主要职责 | 扩展建议 |
| --- | --- | --- |
| `TemplateList` | 展示模板摘要、处理选中态 | 后续可加入搜索、标签过滤与分页 |
| `TemplateDetailPanel` | 动态表单、格式与高级选项配置 | 如需复杂布局，可将字段渲染逻辑拆分为 `FieldRenderer` 子组件；若需富文本编辑可替换为第三方编辑器 |
| `TaskCenter` | 任务轮询、结果下载与重试 | 可接入 WebSocket/SSE 以减少轮询；支持批量下载（Zip）时可在此添加入口 |
| `apiClient` | Axios 实例与下载工具 | 若未来引入鉴权，可在此追加 Token 注入与 401 处理逻辑 |

## 状态管理约定

1. 全局数据（模板列表、任务状态等）统一由 React Query 托管，保持请求与缓存分离。
2. 短生命周期状态（选中模板、告警信息、任务历史）由 `App` 局部状态管理，必要时可拆分为 Context。
3. 表单状态与校验逻辑封装在 `TemplateDetailPanel` 内部，提交时通过 `RenderRequestPayload` 向上抛出，保持组件内聚。
4. 所有异步操作采用 async/await，配合统一的错误提示函数，确保出现异常时界面反馈一致。

## 后续工作建议

- **任务通知增强**：在任务完成后增加浏览器通知或声音提示，提升长耗时任务的可用性。
- **表单草稿保存**：对复杂模板可加入本地草稿功能，防止长时间填写后意外刷新导致内容丢失。
- **多语言与无障碍**：当前文本为中文，可结合 `i18next` 等方案抽象文案，并完善键盘/屏幕阅读器支持。
- **组件测试**：建议使用 React Testing Library 编写关键交互测试，确保模板切换、表单校验、任务轮询等功能稳定。

通过以上约定，前端整体逻辑保持清晰且易于演进，可在后续迭代中按业务需求逐步深化。
