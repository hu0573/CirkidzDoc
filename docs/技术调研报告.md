## docassemble 能力拆分技术调研报告

### 1. 调研目标
1. 明确从 docassemble 中抽离文档模板填充与格式转换能力所需的核心依赖与运行条件。
2. 制定可复用的镜像构建策略，使新服务与原有 docassemble 环境在功能与版本上保持一致。
3. 汇总常见调试场景与故障排查手段，为研发与运维提供操作指南。

### 2. 依赖系统梳理
| 环节 | 依赖/工具 | 版本建议 | 说明 |
| --- | --- | --- | --- |
| DOCX 渲染 | `docxtpl`, `python-docx`, `docxcompose`, `jinja2`, `Pillow` | 与参考项目 docassemble 1.8.18 对齐（`docxtpl`==0.20.1） | 支持图片、子模板、条件逻辑。 |
| PDF 填充 | `xfdfgen`, `pdftk`, `pikepdf`, `qpdf`, `ghostscript` | `pikepdf` ≥ 9.0, `qpdf` ≥ 11.0 | `pdftk` 负责表单填充/扁平化，`pikepdf` 写入字段，`ghostscript` 用于 PDF/A。 |
| 格式转换 | LibreOffice (`soffice`), Pandoc, `unoconv`, ImageMagick | LibreOffice 7.5+, Pandoc 3.x | DOCX → PDF → HTML/RTF/Markdown；图像预处理依赖 ImageMagick。 |
| 环境与工具链 | Python 3.11, `pip`, `uv`, `make`, `just`, Node.js 20 | - | `uv` 用于锁定依赖，Makefile/justfile 管理流程。 |
| 数据存储 | Postgres / SQLite, Redis（可选） | - | 任务元数据、队列状态持久化。 |

### 3. 镜像构建策略
1. **基础镜像选择：** 使用 Ubuntu 22.04 LTS，预装系统包（`libreoffice`, `pandoc`, `ghostscript`, `imagemagick`, `qpdf`, `pdftk`, `poppler-utils`）。
2. **多阶段构建：**  
   - **Stage 1（deps-builder）：** 安装所有重量级系统依赖与 Python 包，生成离线 wheel 缓存。  
   - **Stage 2（runtime）：** 拷贝运行所需的 wheel、node_modules 缓存、配置文件，安装 Python 依赖（`uv pip sync`），创建非 root 用户。  
3. **与 docassemble 对齐：** 参考 `ReferenceProjects/docassemble/Dockerfile` 与各 `pyproject.toml`，对比 `apt`, `pip` 包版本（当前基线为 docassemble 1.8.18）；通过 ADR 记录与原仓库差异。  
4. **构建验证：** 在镜像内执行 `pandoc --version`, `soffice --headless --version`, `qpdf --version`，确保与目标版本一致；运行 `make render-sample` 检查渲染链路。

### 4. 运行与调试指南
- **日志：** 统一使用结构化日志库（`structlog`/`loguru`），将外部命令 stdout/stderr 捕获后写入任务日志。
- **命令执行：** 使用 `asyncio.subprocess` 或 `anyio.run_process` 控制超时、资源占用；提供清晰的错误码映射。
- **健康检查：** 启动时加载模板元数据，检查必要文件存在；定时运行依赖探测脚本（`pandoc --version` 等）。
- **本地开发：** 提供 `docker-compose.yml`，包含 FastAPI、Redis（可选）、LibreOffice/Pandoc 镜像；通过 VS Code Dev Container 对齐环境。
- **回归测试：** 引入示例模板集（DOCX×3, PDF×1），编写 Pytest 集成测试验证渲染/转换结果（可使用快照对比）。

### 5. 版本对齐策略
1. **依赖锁定：** 使用 `uv pip compile` 生成 `uv.lock`，在 CI 中执行 `uv pip sync --locked` 确保一致性。
2. **对比工具：** 编写脚本读取 `ReferenceProjects/docassemble/docassemble_base/pyproject.toml`，生成差异报告。
3. **升级流程：** 先在 dev 分支更新依赖，并运行 `make healthcheck`、集成测试，再合并主干。

### 6. 常见问题与排查
- **LibreOffice 无法启动：** 检查容器中 `/tmp` 权限与字体库；必要时安装 `fonts-noto-cjk`。
- **PDF 扁平化失败：** 多与 `ghostscript` 版本不兼容有关，尝试指定 `-dCompatibilityLevel=1.7`。
- **Pandoc 样式丢失：** 需要提供参考样式文件（CSL/模板），或在转换前执行 `docxcompose` 更新引用。
- **任务超时：** 设置命令超时（120s），并记录耗时指标；对大文件启用异步队列。

### 7. 后续调研方向
- 评估 `borb`, `pdfplumber`, `docx2pdf` 等替代库，在性能与兼容性间取舍。
- 研究使用 `Celery + Redis`/`RQ` 替换内置 BackgroundTasks 的可行性。
- 探索将模板与示例数据存储在对象存储（S3/MinIO）以支持多节点部署。
