# 镜像使用与调试手册

## 1. 背景与目标
本手册用于指导团队在本地或 CI 环境中构建与 docassemble 同源的文档渲染依赖镜像，并通过脚本完成健康检查与渲染 PoC。该镜像服务于后端渲染组件的开发调试，确保与参考项目 `docassemble` 在依赖版本与工具链能力上保持一致。

## 2. 构建计划与组件清单

- **基础镜像**：`ubuntu:22.04`，启用 `deadsnakes/ppa` 安装 Python 3.11。  
- **多阶段结构**：
  1. `base`：安装系统级依赖（LibreOffice、Pandoc、ImageMagick、qpdf、pdftk 等）与 Python 运行时。
  2. `deps-builder`：使用 `uv pip download` 预拉取渲染相关的 Python wheel。
  3. `runtime`：基于 `base` 构建 venv，离线安装 Python 依赖，拷贝脚本并创建非 root 用户。
- **PoC 输出**：`make render-sample` 生成 DOCX/PDF/HTML/Markdown，验证 docx 渲染与格式转换链闭环。

| 分类 | 组件 | 版本/来源 | 说明 |
| --- | --- | --- | --- |
| Python | Python 3.11, `docxtpl`, `python-docx`, `docxcompose`, `pikepdf`, `xfdfgen` | 与 `docassemble 1.8.18` 对齐 | 支撑 DOCX 渲染与 PDF 表单填充。 |
| 转换链 | LibreOffice, Pandoc 3.x, unoconv, qpdf, pdftk-java, ImageMagick, ghostscript | Ubuntu 22.04 仓库 | DOCX → PDF → {HTML, Markdown} 转换与 PDF 扁平化。 |
| 辅助 | fonts-dejavu, fonts-noto-cjk, poppler-utils, tesseract-ocr | Ubuntu 22.04 仓库 | 字体与 PDF 解析/图像处理辅助组件。 |
| 工具链 | `uv`, `make`, Docker Compose | 直接安装 | 依赖预下载、任务编排与命令封装。 |

> **与 ReferenceProjects/docassemble 差异**  
> - 将大型服务（Postgres、Redis、Celery）剥离，仅保留渲染与转换能力。  
> - 固化渲染脚本到 `/opt/scripts`，通过 `Makefile` 暴露 `healthcheck`、`render-sample`。  
> - 预留 `/workspace/tmp`、`/workspace/output` 目录用于挂载宿主机结果，便于调试。

## 3. 项目结构
```
infra/
  Dockerfile               # 多阶段镜像构建
  docker-compose.yml       # 本地运行配置，服务名 toolkit
  python/requirements.txt  # 渲染相关 Python 依赖
  scripts/
    entrypoint.sh          # 统一入口，默认进入 bash
    healthcheck.sh         # 外部工具与 Python 包探测
    render_sample.sh       # 调用 render_sample.py 并展示结果
    render_sample.py       # DOCX 渲染 + LibreOffice/Pandoc 转换示例
  output/                  # 宿主机挂载的结果目录
  tmp/                     # 临时文件目录
Makefile                   # 统一命令封装（build/healthcheck/render-sample 等）
```

## 4. 使用流程
1. **镜像构建**
   ```bash
   make build
   ```
   - 基于 `infra/Dockerfile` 构建镜像 `cirkidzdoc/toolkit:dev`。
   - 如果已存在镜像，可通过 `docker image ls` 校验时间戳。

2. **健康检查**
   ```bash
   make healthcheck
   ```
   - 逐项检查 `python3.11`、`pandoc`、`soffice`、`qpdf`、`pdftk`、`unoconv`、`convert`。
   - 额外执行 Python 模块导入，验证 `docxtpl`、`pikepdf` 等依赖可用。
   - 成功后输出 `所有依赖探测通过 ✅`。

3. **渲染示例 PoC**
   ```bash
   make render-sample
   ```
   - 在容器内生成一个包含占位符的 DOCX 模板，并使用 `docxtpl` 渲染。
   - 通过 LibreOffice 批量转换为 PDF，再由 Pandoc 转换为 HTML 与 Markdown。
   - 产物保存在 `infra/output/`，可直接在宿主机查看：
     - `sample_rendered.docx`
     - `sample_rendered.pdf`
     - `sample_rendered.html`
     - `sample_rendered.md`

4. **进入容器调试**
   ```bash
   make shell
   ```
   - 进入非 root 用户 `appuser` 的 bash 环境，可手动执行转换命令。

5. **环境清理**
   ```bash
   make clean
   docker compose -f infra/docker-compose.yml down --remove-orphans
   ```

## 5. 调试要点与常见问题
- **LibreOffice 启动失败**：确认主机架构为 x86_64；若报字体缺失，可按需在 `Dockerfile` 中追加字体包（如 `fonts-noto-serif`）。
- **ImageMagick 报策略限制**：`convert` 默认启用策略限制，如需处理 PDF → 图像，可在后续阶段复制自定义 `policy.xml`。
- **pikepdf 依赖缺失**：已在镜像中安装 `libqpdf-dev`；若仍出现加载失败，请确认宿主机内核/CPU 支持 AVX2。
- **性能验证**：建议在 CI 中执行 `make healthcheck`，并将 `render-sample` 作为 smoke 测试，确认渲染链闭环。

## 6. 后续扩展建议
- 将 `infra/docker-compose.yml` 扩展为多服务场景，引入 FastAPI 容器与 Redis，支持后续任务编排测试。
- 在 `infra/scripts/` 下追加 `convert_pipeline.sh`，覆盖 DOCX → 多格式的组合调用，为集成测试提供脚手架。
- 与 `ReferenceProjects/docassemble` 持续比对依赖版本，新增 `uv.lock` 与 `ADR` 记录，确保升级透明。

> 当镜像用于正式渲染服务时，建议结合 `deploy/` 目录的 Helm Chart 或 Compose 模板，补充健康检查端点与监控探针。
