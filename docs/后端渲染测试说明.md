# 后端渲染测试说明

## 目标
- 验证 DOCX 渲染服务在动态字段、日期格式与图片嵌入场景下的正确性。
- 验证 PDF 渲染服务对文本字段、复选框字段以及依赖项缺失时的降级表现。
- 验证 `ConversionPipeline` 对 DOCX→PDF/Pandoc 多格式转换流程的控制逻辑。
- 确认健康检查接口能够反映外部依赖状态，并在依赖缺失时进入 `degraded` 状态。

## 测试分层
- **单元测试**：位于 `BackEnd/tests/` 目录，由 `pytest` 执行，依赖最小化并通过 MonkeyPatch 模拟外部工具调用。
- **依赖模拟**：对 Pandoc、LibreOffice、qpdf、Ghostscript 等命令行工具使用 `DummyRunner` 或 MonkeyPatch 截获，确保在本地未安装情况下仍能运行测试。
- **数据构造**：运行时动态生成 DOCX 模板与示例图片，确保测试独立于实际模板仓库。

## 覆盖用例
- `test_docx_renderer.py`
  - 渲染字符串与日期字段，并验证输出文本。
  - 通过图片描述协议（`{"__type": "image"}`）注入 Logo，验证 `InlineImage` 生成。
- `test_pdf_renderer.py`
  - 填充文本、勾选/取消勾选复选框，确保 `/V` 与 `/AS` 字段设置正确。
  - 验证 `NeedAppearances` 自动开启，保证 PDF 阅读器自动渲染外观。
- `test_conversion_pipeline.py`
  - 同时请求 `docx/pdf/html/markdown` 四种输出格式，校验输出路径生成与命令调用顺序。
  - 对不支持格式（如 `pptx`）抛出 `ConversionError`。
- `test_health_api.py`
  - 模拟依赖缺失时返回 `degraded` 状态，并断言依赖矩阵内容。

## 执行方式
```bash
cd BackEnd
uv sync --extra dev      # 首次或依赖更新后执行
uv run pytest            # 或使用 .venv/bin/pytest
```
