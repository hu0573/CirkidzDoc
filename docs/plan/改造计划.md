## 改造目标概览
- 清理现有模板结构，移除预览资源并精简元数据字段。
- 支持用户上传自定义模板并生成初始元数据配置。
- 去除模板转换选项的显式配置，实现默认全能力开放。

## 模板目录调整（BackEnd/templates）
- **移除预览资源**：遍历各模板目录，删除预览图及相关引用，确认前端不再依赖。
- **精简字段定义**：更新 `metadata.json` 结构，仅保留 `name` 与 `type`。清除 `label`、`description`、`required` 等冗余字段，确保生成逻辑默认将所有字段视为必填。
- **元数据格式声明**：统一规范模板元数据仅包含 `id`、`name`、`description`、`entry` 与 `fields`，其中 `fields` 项内每个字段仅保留 `name`、`type`。明确删除历史字段如 `version`、`label`、`required`、`options` 等，避免混淆。
- **结构验证**：在新解析逻辑下完成模板加载自测，确认字段缺省不会触发 KeyError，前端渲染及表单绑定正常。
- **文档同步**：更新现有文档说明，描述新的元数据格式与约束。

## 用户上传模板功能
- **后端接口**：设计上传端点，接收文档文件，基于文件名自动创建 `BackEnd/templates/<新模板名>/`。
- **模板初始化**：
  - 将上传文档保存为模板原文件。
  - 生成基础 `metadata.json`，预填 `id`、`name`、`entry` 等信息，`description` 默认留空，`fields` 数组根据占位符生成 `name`，`type` 初始统一为 `string`，等待用户手动确认或调整。
  - 自动抽取占位符：沿用现有模板语法，识别形如 `{{placeholder}}` 的变量名。允许同名占位符多次出现，生成的字段去重后仅保留一次。
- **引导流程**：返回创建结果与后续指导信息（例如下一步编辑元数据的路径或提示）。
- **权限与校验**：确认文件类型合法性、大小限制与重名冲突处理。
- **默认输出能力**：上传后无需配置 `options`，后端直接使用代码内维护的全量输出格式列表，确保新模板立即支持全部既有转换能力。

## 元数据编辑体验
- **前端交互**：
  - 在模板详情页新增独立的“字段配置”区域，展示从 `metadata.json` 读取的字段列表。
  - 每个字段仅暴露 `name`、`type` 两列，`type` 提供下拉选择（例如 `string`、`number`、`date`），默认选中 `string`。
  - 若文档内存在未在元数据中登记的 `{{placeholder}}`，在界面顶部提示“检测到新占位符”并提供一键补全入口。
  - 删除旧版 UI 中依赖 `label`、`description`、`required`、`validation`、`placeholder` 的表单元素与提示，统一以字段名作为展示标签。
- **后端持久化**：实现更新接口，确保保存后重新加载模板时字段顺序与类型正确。
- **校验逻辑**：在保存前校验字段 `name` 非空、类型在允许列表内。

## options 配置与前端元素清理
- **后端**：删除 `metadata.json` 中 `options` 字段解析与使用逻辑，统一按系统支持的所有输出能力执行。
- **前端**：
  - 移除 `TemplateDetailPanel` 对 `metadata.options` 及 PDF 专属设置（如 `__pdf_flatten`、`__pdf_pdfa`、`__pdf_password`）的处理，同时删除基于 `label`、`description`、`required`、`validation`、`placeholder` 等字段渲染的 UI 与校验逻辑，仅保留使用 `name`、`type` 填值。
  - 删除 `TemplateList` 中版本号展示（`template.version`）及允许输出格式徽标（`template.allowed_outputs`）等依赖旧元数据的元素。
  - 清理 `OutputFormatSelector` 中根据 `metadata.options.allowed_outputs` 生成的格式选择器，改为使用系统默认支持的全量格式列表，不再出现勾选面板。
- **测试与回归**：验证默认能力覆盖现有用例，确保无遗漏功能。

## 验证与发布
- **单元与集成测试**：补充或更新与模板加载、上传、编辑相关的测试。
- **回归检查**：使用现有模板和新上传模板进行端到端验证。
- **文档更新**：在 `docs/` 中记录上传流程、元数据字段规范及无 `options` 的新行为。
- **发布计划**：安排灰度或内测，确认存量模板在新结构下自动迁移完毕后再正式发布。
