## 文档模板填充能力需求规格说明

### 1. 概述
**项目名称：** 文档模板填充能力提取  
**目标：** 在不依赖 docassemble 全栈的前提下，重构其文档模板填充与格式转换能力，提供前后端分离的 Web 应用。  
**范围：** 本说明覆盖 MVP 阶段的功能、数据、约束与验收指标，为后续架构设计与实现提供基准。

### 2. 相关方
- **产品负责人：** 负责需求优先级与验收。
- **研发团队：** 前端、后端、基础设施工程师。
- **模板维护者：** 负责模板包制作、审核与回归测试。
- **运维与 QA：** 负责部署、监控、测试与发布。

### 3. 系统边界与假设
- 系统运行在受信任的内网环境，初期不引入鉴权。
- 模板与生成结果默认存储在本地文件系统，可扩展为对象存储。
- 任务执行支持同步/异步；初期使用 FastAPI BackgroundTasks。
- 外部命令（Pandoc、LibreOffice、ImageMagick、qpdf 等）需预先安装并在容器内可用。

### 4. 功能需求
#### 4.1 模板管理
- F1：提供内置模板列表查询接口，返回模板名称、描述、支持格式、预览图地址。
- F2：提供模板详情接口，返回字段定义、默认值、可选高级选项。
- F3（扩展）：支持模板包上传、版本管理（MVP 外）。

#### 4.2 数据填写与校验
- F4：前端基于元数据动态生成表单，支持文本、数字、布尔、日期、枚举、文件等字段类型。
- F5：提交前执行前端表单校验；后端使用 Pydantic 进行二次校验，并返回字段级错误信息。
- F6：可选提供 JSON 视图模式，允许用户直接编辑数据对象（MVP 可选）。

#### 4.3 渲染与格式转换
- F7：后端支持 DOCX 模板渲染，填充图片、条件逻辑、子模板。
- F8：后端支持 PDF 表单填充，提供扁平化、PDF/A、密码保护等选项。
- F9：转换服务支持 DOCX→PDF→{HTML, RTF, TeX, Markdown} 链路，并具备错误降级策略。

#### 4.4 任务执行与下载
- F10：`POST /api/templates/render` 创建任务，返回 `task_id`。
- F11：`GET /api/templates/{task_id}` 返回任务状态、进度、错误信息与结果文件列表。
- F12：`GET /api/templates/{task_id}/files/{format}` 提供下载链接；支持 Zip 打包。
- F13：提供结果过期策略（默认 7 天）；后台定时清理过期文件。

#### 4.5 监控与诊断
- F14：提供 `/health` 与 `/health/deps` 接口，检查进程与关键依赖。
- F15：生成结构化日志，包含任务 ID、模板 ID、耗时、错误码。
- F16：暴露基本指标（任务耗时、成功率）供 Prometheus 抓取（MVP 可选）。

### 5. 非功能需求
- **性能：** 单个模板渲染+转换应在 10 秒内完成；并发请求需具备队列/限流能力。
- **可靠性：** 渲染失败提供明确错误码与重试提示；服务异常需具备降级策略（仅返回原始 DOCX）。
- **可维护性：** 前后端代码需通过 lint、单元测试；提供 Makefile/justfile 简化常用命令。
- **可扩展性：** 模板元数据满足未来自定义上传、国际化与权限控制需求。
- **安全性：** 文件上传需限制类型与大小；渲染过程中避免执行未授权脚本。

### 6. 数据需求
- 使用 Postgres（或 SQLite 在开发环境）存储模板、任务、结果元数据。
- `metadata.json` 定义模板字段详情，后端加载时需缓存并监测版本变更。
- 临时文件在 `temp` 目录创建；结果归档于 `results/<task_id>/` 并生成下载 token。

### 7. 系统接口
- REST API 见 `F10-F12` 条款；所有接口返回统一响应格式：
```json
{
  "success": true,
  "data": {},
  "error": {
    "code": "string",
    "message": "string",
    "details": {}
  }
}
```
- 支持 `Accept: application/json` 与附件下载 (`application/octet-stream`)。
- 前端使用 Axios 客户端，统一处理错误拦截、文件下载。

### 8. 运行环境与约束
- **后端：** Python 3.11，FastAPI + Uvicorn，依赖 `uv` 管理；运行于容器（Ubuntu 基础镜像）。
- **前端：** Vite + React + TypeScript + Tailwind，Node.js 20 环境。
- **外部工具：** Pandoc ≥ 3.x、LibreOffice ≥ 7.x、ImageMagick、Ghostscript、qpdf、pikepdf、docxtpl 等。
- **部署形态：** 本地使用 Docker Compose；生产建议使用容器编排（Kubernetes/Swarm）。

### 9. 验收标准
- 至少 3 个 DOCX、1 个 PDF 模板通过渲染与转换全流程测试。
- 支持 DOCX、PDF、HTML、Markdown 输出格式，内容与样式满足模板要求。
- 任务失败时返回明确错误码、追踪 ID，前端展示友好提示。
- 发布前提供《测试报告.md》《部署指南》。

### 10. 版本计划与风险
- **阶段里程碑：** 环境对齐 → 后端渲染基础 → 前端交互与下载 → 性能与验证。
- **关键风险：** 依赖安装复杂度、模板兼容性、转换性能；需通过容器化、示例库与性能基线缓解。
- **后续扩展：** 模板上传、国际化界面、任务队列（Celery）、对象存储集成。
