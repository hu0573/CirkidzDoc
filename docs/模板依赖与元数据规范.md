## 模板依赖与元数据规范

### 背景
为确保从 docassemble 迁移出的模板填充能力在全新后台服务中可复用，本规范整理 docassemble 现有模板与输出格式能力所依赖的核心组件，并定义统一的模板元数据结构与字段校验规则，为后续服务实现与测试提供依据。

### 模板输出能力与依赖矩阵
| 模板类型 | 主要渲染步骤 | 支持输出格式 | 关键依赖组件 | 说明 |
| --- | --- | --- | --- | --- |
| DOCX (`docx_template_file`) | Jinja2 → docxtpl → python-docx → docxcompose | docx, pdf, html, rtf, tex, markdown | `docxtpl`, `python-docx`, `docxcompose`, LibreOffice (`soffice`), Pandoc, ImageMagick | DOCX 作为基础产物，通过 LibreOffice 转换 PDF，再经 Pandoc 生成 HTML/Markdown/TeX/RTF；图片处理需 ImageMagick。 |
| PDF (`pdf_template_file`) | XFDF 生成 → pdftk/pikepdf → qpdf | pdf（可选扁平化、PDF/A、加密） | `xfdfgen`, `pdftk`, `pikepdf`, `qpdf`, `ghostscript` | `pdftk` 负责表单填充与扁平化，`pikepdf` 写入字段；PDF/A 依赖 `ghostscript`；密码保护由 qpdf 实现。 |
| RTF (`rtf_template_file`) | 模板合并 → LibreOffice 转换 | rtf, docx, pdf, html | LibreOffice, Pandoc | RTF 模板填充后通常需转换为 DOCX/HTML；对样式兼容要求较高。 |
| 手动附件 (`attachment`) | 直接打包 | 任意 | 系统文件存储 | 用于附加静态文件，不经过渲染或转换。 |

#### 高级功能与依赖
- PDF/A：`ghostscript`, `qpdf`
- 扁平化：`pdftk`（`flatten`）或 `ghostscript`
- 图像嵌入：`docxtpl`, `Pillow`
- 超链接样式/引用更新：`python-docx`, `docxcompose`
- 子模板合并：`docxcompose`, `jinja2`

### 模板元数据结构
模板目录约定为 `templates/<template_id>/`，包含主模板文件及其元数据。`metadata.json` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 模板唯一标识，采用 kebab-case。 |
| `name` | string | 是 | 模板显示名称；默认根据文件名自动生成。 |
| `description` | string | 否 | 模板描述，默认留空，可手动补充。 |
| `entry` | string | 是 | 主模板文件相对路径（通常为 `.docx`）。 |
| `fields` | FieldSchema[] | 是 | 字段定义列表（仅包含 `name` 与 `type`）。 |

> 说明：历史字段（如 `version`、`preview`、`options` 等）已移除。渲染端会自动开放目前支持的全部输出格式，无需额外配置。

上传模板后，系统会：
1. 对上传文件名做 kebab-case 归一化，生成模板目录与 `id`，并处理重名（附加数字后缀）。
2. 将原始 DOCX 保存为模板入口文件，入口文件名保持上传时的大小写。
3. 扫描模板内 `{{placeholder}}` 占位符，去重后生成 `fields` 数组，字段类型默认设为 `string`，可在 `metadata.json` 中手动调整。

### 字段类型结构
`FieldSchema` 结构示例：
```json
{
  "name": "party_a_name",
  "type": "string"
}
```

当前允许的 `type` 枚举值与推荐控件：

| `type` | 推荐前端控件 | 备注 |
| --- | --- | --- |
| `string` | 单行文本输入框 | 默认类型；任何未知字段会回退到 `string`。 |
| `textarea` / `richtext` | 多行文本 / 富文本编辑器 | `richtext` 仍需额外富文本管控。 |
| `number` | 数值输入框 | 用于整数或浮点值。 |
| `boolean` | 复选框 / 开关 | | 
| `date` | 日期选择器 | 需使用 ISO8601 格式提交数据。 |
| `enum` | 下拉选择 | 仍可与占位符结合渲染固定选项。 |
| `file` | 文件上传控件 | 值为 Base64 编码字符串。 |

> 前端会以字段 `name` 直接作为展示标签；若需别名、校验规则等高级配置，可在后续版本扩展配置文件或 UI 层逻辑。

### 字段类型映射与校验
`FieldSchema` 结构：
```json
{
  "name": "party_a_name",
  "label": "甲方名称",
  "type": "string",
  "required": true,
  "placeholder": "请输入公司名称",
  "default": "",
  "validation": {
    "pattern": "^[\\u4e00-\\u9fa5A-Za-z0-9（）()]{2,60}$",
    "message": "名称需为2-60个字符，可包含中文括号"
  },
  "options": {
    "enum": ["option_a", "option_b"]
  },
  "depends_on": {
    "field": "need_extra_clause",
    "value": true
  }
}
```

字段类型与前端控件映射表：

| `type` | 前端控件 | 数据校验 | 备注 |
| --- | --- | --- | --- |
| `string` | 单行文本输入 | `minLength`, `maxLength`, `pattern` | 默认 UTF-8，支持大小写转换选项。 |
| `textarea` / `richtext` | 多行文本 / 富文本编辑器 | 长度限制、富文本白名单 | 富文本需额外消毒策略。 |
| `number` | 数值输入 | `minimum`, `maximum`, `multipleOf` | 支持整数/浮点类型，前端使用 `input[type=number]`。 |
| `boolean` | 单选开关或复选框 | - | 支持默认值与禁用状态。 |
| `date` | 日期选择 | ISO8601 格式校验 | 扩展支持时间区间（`date_range`）。 |
| `enum` | 下拉列表 / 单选组 | 枚举值存在性 | 支持 `enumLabels` 指定显示文本。 |
| `file` | 文件上传控件 | MIME、文件大小上限 | 需声明允许的文件类型与最大尺寸。 |

字段通用校验规则：
- 服务端再验证：所有校验在后端使用 Pydantic + 自定义逻辑复验，避免绕过。
- 依赖关系：`depends_on` 支持简单布尔表达式；复杂逻辑后续可扩展 DSL。
- 默认值策略：若 `default` 未设置，按类型使用空字符串、`false`、`null` 或 `[]`。
- 国际化：`label`、`placeholder`、`validation.message` 支持 `{ "zh-CN": "...", "en-US": "..." }` 格式。

### 结论与后续行动
1. 继续维护依赖安装脚本，确保 DOCX/PDF 转换链工具版本与 docassemble 对齐。
2. 基于精简后的 `metadata.json` 结构补充 JSON Schema 校验，保证上传模板的字段定义合法。
3. 前端表单渲染将直接使用 `FieldSchema`，并在 UI 层提供字段类型调整、增删能力。
